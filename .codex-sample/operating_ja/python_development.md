# Python開発共通ルール

## 基本方針

- Python 3.11以上を対象とする。ただし既存プロジェクトが別バージョンを明示している場合は、その制約を優先する。
- 既存コード、ディレクトリ構成、依存管理、formatter、linter、型チェック、テスト方式を先に確認する。
- `pyproject.toml`、pytest、ruff、mypy、pyright、uv、Poetry等を無条件に導入しない。
- ライブラリ、API、フレームワーク、設定項目は、可能な限りContext7 MCPまたは公式情報で現行仕様を確認する。

## 変更と依存

- 目的に必要な最小範囲を変更し、無関係なリファクタリングを混ぜない。
- 標準ライブラリまたは既存依存で十分な場合は、新規依存を追加しない。
- 依存追加時は導入理由、代替、互換性、ライセンス、固定方法、削除方法を確認する。
- lockファイルや生成ファイルは、既存プロジェクトの管理方針に従う。

## データとファイルI/O

- 入力データを既定で上書きしない。派生結果は別ファイルまたは明示された出力先へ保存する。
- 文字コード、改行、区切り、型、欠損、重複、日付、単位を明示的に扱う。
- 書込み失敗時に中途半端な成果物を残さない方法を検討する。
- 大量データではメモリ使用量と処理時間を確認する。

## セキュリティと外部通信

- APIキー、トークン、パスワード、個人情報をコード、設定例、ログ、例外メッセージへ埋め込まない。
- 外部通信にはtimeoutを設定し、retryは冪等性と相手側制限を確認してから使う。
- URL、ファイルパス、コマンド引数、外部応答を信頼せず検証する。
- Web収集では利用規約、robots.txt、著作権、アクセス頻度、取得対象の機密性を確認する。

## テストと完了報告

- 変更リスクに応じて正常系、異常系、境界値、回帰テストを追加または実行する。
- 外部APIや時刻に依存する処理は、再現可能なテスト方法を検討する。
- formatter、linter、型チェックは既存設定がある場合に実行する。
- 完了時は変更内容、実行コマンド、検証結果、未実行項目、残存リスクを報告する。
