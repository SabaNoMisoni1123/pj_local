# 参照禁止ソースの扱い

## 1. 目的

人間が意図的に古い情報と判断して退避した場所を、AIエージェントが現在情報の根拠や推測材料として使わないようにします。

## 2. 対象

パス区切りで独立したディレクトリ名が次に該当する場合、そのディレクトリ配下は参照禁止ソースとして扱います。大文字小文字は区別しません。

- `old`
- `_old`
- `old_...`、`..._old`、`old-...`、`...-old` など、`old` が旧版退避を示す独立した語として読めるディレクトリ

単語の一部として偶然 `old` を含む通常ディレクトリは、旧版退避の意図が明確でない限りこの対象にしません。

## 3. 禁止事項

参照禁止ソース配下について、通常業務では次を行いません。

- ファイル本文を開く、読む、要約する。
- ファイル名、フォルダ名、更新日時、メタデータから内容や状態を推測する。
- 根拠、出所、比較対象、矛盾確認、用語確認、TODO抽出、意思決定確認に使う。
- `project-context`、`source-map`、索引、議事録、レビュー、調査メモなどに根拠として記録する。
- サブエージェント、MCP、変換ツール、全文検索ツールに配下の内容確認を依頼する。

参照禁止ソースは、低信頼ソースより強い扱いです。低信頼ソースのように「明記すれば補助的に使える」ものではありません。

## 4. 許容される扱い

必要な場合に限り、参照禁止ディレクトリの存在を次の範囲で記録できます。

- ディレクトリパス
- `old/_old 系の参照禁止ディレクトリのため内容未確認` という除外理由

配下のファイル一覧、ファイル名、更新日時、件数、内容推定は記録しません。

旧版ディレクトリ自体の整理、削除候補確認、復旧調査などをユーザーが明示的に依頼した場合だけ、目的と範囲を確認したうえで必要最小限に確認します。その場合でも、現在情報の根拠としては扱いません。

## 5. 探索時の実務

ファイル探索、全文検索、索引作成では、可能な限り最初から参照禁止ディレクトリを除外します。

例:

```text
rg --files --glob '!old/**' --glob '!**/old/**' --glob '!_old/**' --glob '!**/_old/**'
rg "検索語" --glob '!old/**' --glob '!**/old/**' --glob '!_old/**' --glob '!**/_old/**'
```

`old_...`、`..._old`、`old-...`、`...-old` なども対象にする場合は、同様に該当するディレクトリパターンを除外します。

探索結果に参照禁止ディレクトリ配下のパスが混入した場合、そのパスは開かず、内容推定にも使いません。
