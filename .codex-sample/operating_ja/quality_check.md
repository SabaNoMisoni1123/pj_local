# 品質チェック

## 1. 共通品質基準

- プロジェクト内情報との整合性を重視する。
- 主張と根拠を対応させる。
- 数値、日付、用語、タスクの整合性を確認する。
- わからないことは `不明` と明示する。
- 不足情報は `要確認` として提案する。
- 内容品質を装飾品質より優先する。

## 2. 主張と根拠

確認項目:

- 主張ごとに根拠ファイルがあるか
- 根拠箇所が特定できるか
- 根拠が `old/`、`_old/` 等の参照禁止ディレクトリ配下ではないか
- 根拠が一次資料か、低信頼ファイルか
- `_gpt` / `_tmp` 等のファイルを単独根拠にしていないか
- 推測が事実として書かれていないか

判断区分:

- `事実`: 根拠資料で確認できる
- `推測`: 根拠はあるが明示されていない
- `不明`: 根拠資料で確認できない
- `要確認`: 関係者確認または追加資料が必要

## 3. 数値整合

確認項目:

- 金額、件数、割合、期間、ページ数、表番号
- 単位、桁、丸め、合計値
- 本文、表、図、脚注間の一致
- 前後資料との数値差分

不一致がある場合は、正しい値を推測せず `要確認` とします。

## 4. 日付整合

確認項目:

- 会議日
- 提出日
- 期限
- 対象期間
- 年度
- 更新日

相対日付は、根拠がある場合のみ絶対日付に直します。

## 5. 用語揺れ

確認項目:

- 組織名
- 部署名
- 役職名
- 成果物名
- 略称
- 英日表記
- 固有名詞

正式表記が不明な場合は、候補と追加確認事項を出します。

## 6. TODO漏れ

確認項目:

- 明示的な依頼
- 宿題
- 未決事項
- 決定待ち
- 期限付き作業
- 担当者付き作業
- リスク対応

担当や期限が不明な場合は補完せず `不明` とします。
