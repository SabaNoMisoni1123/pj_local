# 共通ワークフロー

## 1. 初回確認

1. プロジェクトフォルダの `AGENTS.md` を確認する。
2. プロジェクト固有の保存先、命名規則、禁止事項を確認する。
3. 対象ファイル群とフォルダ構成を確認する。
4. `excluded_sources.md` に従い、`old/`、`_old/` 等の参照禁止ディレクトリを除外する。
5. `low_confidence_sources.md` に従い、低信頼ファイルや低信頼フォルダを分類する。
6. `project_intake.md` に沿って不足情報を整理する。
7. 不足情報は推測せず、追加確認事項として出力する。

## 2. 資料確認

1. 対象ファイルの存在を確認する。
2. 参照禁止ディレクトリ配下のファイルを対象から外す。
3. 一次資料、既存Markdown、生成ファイル、公開情報の順で情報源を分類する。
4. 根拠箇所を特定できるか確認する。
5. 文字化け、抽出漏れ、添付欠落の有無を確認する。

## 3. 成果物作成

1. 目的と出力形式を確認する。
2. 根拠に基づく事項だけを `事実` とする。
3. 推測は推測理由と根拠不足を併記する。
4. 根拠がない事項は `不明` または `要確認` とする。
5. 派生成果物は原則として新規ファイルとして出力する。既存ファイルを編集する場合は、ユーザーの明示指示とプロジェクトルールを確認する。
6. 作業後に未確認事項と実行できなかった検証を明記する。

## 4. 更新が必要な場合

以下が確認された場合、プロジェクト固有のproject context更新案を作成します。

- 新規会議
- 期限変更
- 成果物変更
- 主要論点変更
- リスク更新
- クライアント、報告先、会議体の変更
- 重要タスクの追加、完了、遅延

既存のproject contextを直接編集せず、更新案を新規ファイルとして作ることを標準とします。
