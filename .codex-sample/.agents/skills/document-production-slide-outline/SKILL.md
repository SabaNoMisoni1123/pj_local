# Document Production Slide Outline Workflow

## Purpose

Create slide outlines that make the audience, storyline, key messages, evidence, and visual exhibits explicit before slide production.

## Source Material Handling

When source decks, PDFs, Word files, spreadsheets, or other non-text artifacts are needed, use the markitdown-mcp server to convert supported files to Markdown for content review. Treat converted Markdown as a derived aid, cite the original source files, and flag evidence or visual requirements that may depend on lost layout, charts, images, formulas, speaker notes, or slide formatting.

## Workflow

1. Confirm the purpose, audience, presentation setting, required length, format, and delivery constraints.
2. Identify the main message, desired audience action, and non-negotiable points.
3. Build the deck storyline from context to findings, implications, recommendations, and next steps.
4. Define one primary message per slide.
5. For each slide, specify title, message, supporting evidence, proposed visual, required source, and open issues.
6. Separate confirmed content from placeholders, assumptions, and items requiring confirmation.
7. Check flow across slides for duplication, missing bridges, unsupported claims, and excessive detail.
8. Suggest appendix pages when useful detail would distract from the main storyline.

## Output

Use Japanese unless the user requests another language.

Recommended sections:

- 資料目的
- 想定読者・利用場面
- 全体メッセージ
- 構成案
- スライド別アウトライン
- 図表・ビジュアル案
- 必要な根拠・素材
- 未確定事項
- 次の作業

For slide-by-slide outlines, use columns such as:

- ページ
- 章
- スライドタイトル
- キーメッセージ
- 掲載内容
- 図表案
- 根拠・出所
- 要確認

## Quality Criteria

- Keep slide titles message-oriented where appropriate.
- Do not use a slide to carry multiple unrelated messages.
- Make evidence requirements visible before drafting polished text.
- Avoid decorative visuals that do not help the audience understand the point.
- Mark speculative recommendations and missing data clearly.
