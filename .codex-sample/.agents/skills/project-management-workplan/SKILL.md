# Project Management Workplan Workflow

## Purpose

Turn goals, constraints, and available evidence into a practical workplan.

## Source Material Handling

When existing plans, source materials, or constraints are in non-text formats, use the markitdown-mcp server to convert supported files to Markdown when direct reading is impractical. Treat converted Markdown as a derived aid and keep source-backed constraints separate from planning assumptions.

## Workflow

1. Confirm the objective and constraints.
2. Identify inputs, dependencies, stakeholders, milestones, and unknowns.
3. Propose task sequence and decision points.
4. Separate confirmed facts from assumptions.
5. Include open questions and required confirmations.

## Output

Use Japanese unless the user requests another language.

Recommended sections:

- 目的
- 前提・制約
- 作業方針
- タスク分解
- マイルストーン
- 役割分担
- 依存関係
- リスク・論点
- 直近アクション

## Quality Checks

- Tie each task to a deliverable, decision, or risk reduction purpose.
- Make dependencies, owners, due dates, and unresolved assumptions explicit.
- Avoid plans that exceed confirmed scope, schedule, or available inputs.
- Separate immediate next actions from later options.

## Common Operating Rules

Follow the active project AGENTS.md and the common rules under `operating_ja/`, especially workflow, source confidence, naming rules, output location, and quality checks.

## Portability

This skill must remain project-agnostic. Do not store project-specific facts or working notes inside this skill directory.
