# `.codex-python` 開発方針アンケート

作成日: 2026-06-01  
目的: Python ツール開発向け Codex 指示文セットの初期スコープを確定する

以下に回答してください。未定の項目は「未定」または「Codex に推奨案を出してほしい」で問題ありません。

## 1. 想定利用者

1. 主な利用者は誰ですか。
   - 例: 研究員本人、チームメンバー、Python 初学者、一定経験のある開発者、非エンジニア中心
   - 研究員本人が利用。 python を日常利用する一定程度の経験者だが、エンジニアレベルではない。

2. 利用者の Python 経験値はどの程度を想定しますか。
   - 例: 初級、初中級、中級、上級、混在
   - 中級から上級程度。基本的な構文やデータサイエンスに関する知識はある。ただし最新の動向や、システム開発におけるアーキテクチャといった業務レベルの知識はない。

3. Codex に期待する役割はどれに近いですか。
   - 例: コードを書く補助、設計レビュー、テスト作成、データ処理の安全確認、運用手順作成、全部
   - pythonを通じたアプリケーション、システムの開発のすべて。

## 2. 主な開発対象

1. `.codex-python` で最も支援したい Python 開発タスクは何ですか。
   - 例: CLI ツール、CSV/Excel 処理、API 連携、スクレイピング、分析 notebook、ローカル DB、GUI、社内自動化
   - CLIツールの開発タスクを任せたい。
   - 対象とするのは CSV/Excel処理や、スクレイピング、データ分析（グラフ化・可視化）

2. 初期リリースで必ず含めたい skill はありますか。
    - 特段ないです。

3. 初期リリースでは後回しにしてよい領域はありますか。
    - 後回しというのは良くないですね。指示を踏まえて必要なものは実装してほしいですし、そうではないものは指示を待ってください。

## 3. 技術方針

1. 想定する Python バージョンはありますか。
   - 3.11 以上。

2. 依存管理ツールの既定候補はありますか。
    - プロジェクトごとに判断が必要です。ただし、linux（ubuntu）環境では pyenvを想定してください。windows環境ではPIMです。

3. テストツールの既定候補はありますか。
   - プロジェクトごとに判断してください。

4. formatter / linter / 型チェックの既定候補はありますか。
    - プロジェクトごとに判断してください。

5. `pyproject.toml` を標準前提にしますか。
    - 前提にしません。

## 4. 安全性・運用

1. 業務データ処理で特に重視したい安全ルールはありますか。
    - 特段ありません。

2. 外部 API 連携や認証情報を扱う skill を初期リリースに含めますか。
    - 特段ありません。

3. スクレイピング支援を含めますか。
    - 含めます。

4. AI 生成コードに対して、特に厳しく確認したい観点はありますか。
    - 保守性を重視します。人間が自力でメンテナンスできるようコメントアウトはしっかりと入れてください。

## 5. ディレクトリ・標準仕様

1. ユーザー依頼文では `.agent` とありましたが、既存 `.codex-sample` と同じく `.agents/skills/` を正式採用してよいですか。
    - `.agents/skills/` としてください。 `.agent`は、ミスです。

2. `.codex-python` は、`.codex-sample` と同じく移植可能な雛形だけを置く場所としてよいですか。
    - その通りです。移植を前提としているのですから、移植可能なひな形のみを含めてください。

3. `project-local/` の空テンプレートを `.codex-python` に含めますか。
    - 含めてください。

4. `.codex-python/config.toml` に Codex 固有設定の最小雛形を含めますか。
    - 提案の通り、固有設定の最小ひな型としてください。

## 6. 公開情報・引用

1. 公開 skill や公開リポジトリの内容を、どの程度取り込みたいですか。
    - 可能であれば積極的に利用してください。

2. 公式ドキュメント確認の対象として優先したいライブラリやツールはありますか。
    - 特段ありません。

3. Context7 MCP で確認できない場合、公式 Web ドキュメントを参照してよいですか。
    - ぜひ参照してください。

## 7. 成果物の粒度

1. 初期リリースはどの粒度を希望しますか。
    - 最小: AGENTS、主要運用ルール、優先度 A skill のみ
    - 標準: 最小 + テンプレート + 主要 domain 説明
    - 包括: 標準 + 優先度 B/C skill + evals
    - 標準程度の粒度を希望します。

2. 各 `SKILL.md` は簡潔な運用手順中心にしますか、それとも詳細なチェックリストを含めますか。
    - 簡潔な運用手順のみとしてください。

3. 日本語と英語の使い分けについて希望はありますか。
    - 例: 説明は日本語、skill 本文は英語、すべて日本語、コード関連だけ英語可
    - えじぇんと向けの言語は英語、それ以外（特に出力データ）は日本語としてください。

## 8. 優先順位

1. 次のうち、優先度が高いものを 5 つ選んでください。
    - CLI ツール作成
    - CSV/Excel/JSON データ処理
    - API 連携
    - 依存管理
    - パッケージ化

2. 最初に実装してほしい具体的なユースケースがあれば書いてください。

## 9. その他

1. `.codex-python` の名称はこのままでよいですか。
    - そのまま

2. 既存 `.codex-sample` と将来的に統合・相互参照したいですか。それとも独立した雛形として管理したいですか。
    - 統合しない。目的が全然違う。

3. その他、避けたい設計、必ず入れたい運用ルール、過去に困った Python 開発上の問題があれば書いてください。

## 回答後の進め方

回答を受けた後、次の順で進めます。

1. 初期スコープを確定する。
2. `.codex-python` 情報設計書を作成する。
3. 優先度 A のファイル一覧を確定する。
4. `.codex-python` の初期雛形を作成する。
5. 品質監査を行い、必要な修正を反映する。
