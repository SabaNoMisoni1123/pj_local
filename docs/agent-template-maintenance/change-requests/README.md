# Codex設定改善リクエスト

## 目的

実際の業務利用で見つかった Codex 設定、`AGENTS.md`、`.codex-sample`、skill、運用ルール、テンプレートの修正・更新・機能追加要望を、Markdown 形式で受け付け、検討し、反映状況を追跡する。

このディレクトリは、本テンプレート管理プロジェクトの保守資料置き場であり、移植先プロジェクトへそのまま配布する雛形ではない。

## 配置

```text
docs/agent-template-maintenance/change-requests/
├─ README.md
├─ request-index.md
├─ change_request_template.md
├─ CR-YYYYMMDD-短い内容.md
└─ archived/
```

## 新規リクエストの作成

1. `change_request_template.md` を基に、新規ファイルを作成する。
2. ファイル名は `CR-YYYYMMDD-短い内容.md` とする。
3. ステータス初期値は `未確認` とする。
4. `request-index.md` に1行追加する。
5. 実案件の顧客名、人名、機密ファイル名、メール本文、認証情報は記載しない。必要な場合は抽象化またはマスクする。

## ステータス

| ステータス | 意味 |
|---|---|
| `未確認` | 起票直後で、内容確認が未了。 |
| `受付済み` | 管理対象として受け付けた。 |
| `確認中` | 影響範囲、再現性、既存ルールとの関係を確認している。 |
| `採用` | `.codex-sample` または本プロジェクトの保守ルールへ反映する。 |
| `一部採用` | 一部だけ反映する。反映しない部分の理由を記録する。 |
| `保留` | 有効性はあるが、現時点では反映しない。 |
| `却下` | 汎用雛形として不適、既存ルールと矛盾、または根拠不足のため反映しない。 |
| `実装済み` | 反映と検証が完了した。 |
| `アーカイブ済み` | 対応済みまたは失効したため `archived/` に移動した。 |

## 反映ワークフロー

1. リクエスト本文と `request-index.md` を読む。
2. 対象を分類する: `AGENTS.md`、Codex設定、skill、運用ルール、テンプレート、ドキュメント、スクリプト、その他。
3. `.codex-sample` に入れるべき汎用部品か、本プロジェクトだけの保守資料かを判定する。
4. 既存ルールとの重複、矛盾、弱体化、案件固有情報の混入を確認する。
5. 採用または一部採用の場合だけ、対象ファイルを編集する。
6. 変更後に必要な検証を行う。例: `SKILL.md` frontmatter、UTF-8 BOM、リンク、スクリプト、カタログ整合。
7. リクエスト本文の「対応記録」と `request-index.md` を更新する。

## 反映判断

`.codex-sample` へ反映してよいのは、移植先プロジェクトで汎用的に使える設定、運用ルール、skill、テンプレートだけとする。

次の内容は `.codex-sample` へ直接反映しない。

- 実案件の固有情報。
- 特定顧客、特定部署、特定ファイル構成だけに依存する要望。
- 未検証の一時的な回避策。
- 既存の上位ルールを弱める変更。
- Codex の内部ログ、セッション、キャッシュ、認証情報に関する実データ。

## 関連する移植用部品

移植先プロジェクトで改善要望を起票する場合は、`.codex-sample/templates/codex_change_request_template.md` と `.codex-sample/.agents/skills/ai-operations-change-request/SKILL.md` を使う。
